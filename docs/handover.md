# Передача коду клієнту (Yagoda CRM)

Внутрішня інструкція. Описує, як зібрати архів вихідного коду, заповнити Акт
приймання-передачі й підписати договори. Цей файл клієнту не передається
(команда в кроці 2 виключає його з архіву).

Договори:

- Договір про передання виключних майнових прав + Акт (Додаток 1):
  https://claude.ai/code/artifact/ac9df756-0faa-466f-8d1e-d3eddfb58ec8
- Договір про обробку персональних даних:
  https://claude.ai/code/artifact/6f6e1358-41a0-47ec-8a01-f95aa04d4241

## Перед початком

- [ ] Клієнт **повністю оплатив** розробку, гроші на рахунку. Договір містить
      підтвердження повної оплати, тому підпис до оплати позбавляє права
      вимагати борг.
- [ ] Усе, що має потрапити до клієнта, змерджено в `main`.
- [ ] `npm run verify:full` на `main` зелений.

## 1. Зафіксувати версію

```bash
git checkout main && git pull
git rev-parse HEAD          # хеш коміту — піде в Акт
```

## 2. Зібрати архів

Архів містить файли репозиторію станом на `main`, **без історії комітів**
(п. 3.2 Договору) і без внутрішніх матеріалів.

```bash
DATE=$(date +%F)
git archive --format=zip --prefix=yagoda-crm/ \
  -o "../yagoda-crm-$DATE.zip" main -- . \
  ':(exclude).claude' \
  ':(exclude)docs/meetings' \
  ':(exclude)docs/superpowers' \
  ':(exclude)docs/handover.md'
```

`git archive` бере лише закомічені файли, тому `.env`, `node_modules`,
`uploads` і незакомічені зміни в архів не потрапляють.

Що виключено і чому:

| Шлях | Причина |
|------|---------|
| `.git` (історія) | імена та e-mail розробників, робочі коміти |
| `.claude/` | внутрішні інструменти розробки |
| `docs/meetings/` | транскрипти зустрічей |
| `docs/superpowers/` | внутрішні плани та специфікації |
| `docs/handover.md` | ця інструкція |

## 3. Перевірити архів

```bash
ZIP="../yagoda-crm-$DATE.zip"
unzip -l "$ZIP" | tail -1                      # кількість файлів
unzip -Z1 "$ZIP" | grep -E '/(\.claude|\.git)/|docs/(meetings|superpowers)/|\.env$' \
  && echo "СТОП: в архіві зайве" || echo "OK"
```

Має надрукувати `OK`. `.env.example` в архіві — це нормально.

## 4. Порахувати контрольну суму

```bash
shasum -a 256 "$ZIP"        # macOS / Linux
# Windows: certutil -hashfile yagoda-crm-<дата>.zip SHA256
```

## 5. Заповнити Акт (Додаток 1)

У пункті 1 Акта вписати:

- ім'я файлу архіву;
- SHA-256 з кроку 4;
- хеш коміту з кроку 1;
- дату Договору і дату Акта (реальний день підписання).

Дата в обох договорах має збігатися з днем підписання.

## 6. Підписати й передати

1. Експортувати обидва договори в PDF.
2. Підписати: КЕП або обмін підписаними скан-копіями (п. 10.2 Договору).
3. Надіслати архів клієнту електронною поштою та посиланням для завантаження
   (п. 3.2) — протягом 5 робочих днів після підписання (п. 3.1).
4. Клієнт підписує Акт або надає зауваження протягом 5 робочих днів (п. 3.5).
   Права переходять до клієнта в день підписання Акта (п. 2.6).

## Що не передається

- `.env`, паролі, ключі;
- доступи до хостингу й домену — продукт працює на нашому хостингу та
  субдомені (п. 3.3);
- база даних. Копію бази й завантажених файлів клієнт отримує лише в разі
  переїзду на власний хостинг або після припинення договору — за договором
  про обробку даних (п. 8.2).

## Після передачі

- Репозиторій залишається в нас, поки триває підтримка; використовуємо його
  лише для неї (п. 3.4). Репозиторій має бути приватним.
- Протягом 90 днів після припинення підтримки видалити копії коду (п. 3.4) і
  персональні дані клієнта (п. 8.2 договору про обробку даних).
- Код клієнта не передавати, не публікувати й не переносити в інші проєкти
  повністю або в суттєвій частині протягом 3 років від дати Акта (розділ 5).
  Базовий шаблон Web Starter і типовий код використовувати можна.
